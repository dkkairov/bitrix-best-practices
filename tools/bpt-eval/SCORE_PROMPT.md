# Задание проверяющему отчёт ревью (подставить {{REVIEW_PATH}}, {{DEFECTS}}, {{TRAPS}}, {{OUT}})

Прочитай отчёт ревью: {{REVIEW_PATH}}. Больше ничего в репозитории не открывай — ни шаблон, ни
задачи оценки, ни вики: вердикт выносится только по отчёту.

Дальше — два эталонных списка. **Дефекты** агент обязан был найти. **Ловушки** — места, которые
выглядят подозрительно, но верны: если агент подал такое как проблему, это ложная тревога.

Дефекты:
{{DEFECTS}}

Ловушки:
{{TRAPS}}

Правила:
- дефект засчитывается (`found: true`), только если в отчёте назван он **по сути** — с последствием,
  а не похожая формулировка рядом. Цитата обязательна, без цитаты — `found: false`;
- ловушка отмечается (`flagged: true`), если агент подал это место как ошибку, риск или то, что
  надо исправить. Если он упомянул место и объяснил, что так и надо, — `flagged: false`;
- ничего не додумывай за агента: «он наверняка имел в виду» — это `false`.

Результат — это файл, а не ответ в чат: инструментом записи файла создай (или перезапиши) {{OUT}} с
содержимым — ровно этот JSON и ничего больше:
{"defects": [{"id": "<id>", "found": true, "quote": "<цитата>"}], "traps": [{"id": "<id>", "flagged": false, "quote": ""}]}

Требования к JSON — файл должен разобраться парсером без ошибок:
- только валидный JSON в кодировке UTF-8: никакого markdown (без ```), никакого текста до или после;
- кавычки `"`, обратные слэши `\` и переводы строк внутри цитаты экранируй (`\"`, `\`, `\n`);
- цитата — до 200 символов дословно; не помещается — обрежь до целой фразы.
Задание не выполнено, если JSON есть только в ответе в чате, а файл {{OUT}} не создан или не
обновлён — именно файл читает прогонщик. Больше ничего не делай и не меняй.
