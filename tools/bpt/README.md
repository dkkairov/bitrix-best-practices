# bpt.php — утилита для шаблонов бизнес-процессов (.bpt)

Разбор, сборка и проверка экспортированных шаблонов БП Bitrix24. Формат описан в вики:
[concept-bizproc-bpt-format](../../wiki/modules/bizproc/concept-bizproc-bpt-format.md).

**Требования:** PHP ≥ 8.1 с расширениями `zlib`, `json`, `mbstring`. Запуск — из корня репозитория.

## Команды

| Команда | Что делает |
|---------|-----------|
| `decode <file.bpt> [-o out.bpt.json]` | `.bpt` → JSON **без потерь** (по умолчанию в stdout) |
| `encode <file.json> -o <out.bpt> [--force]` | JSON → `.bpt`; существующий файл без `--force` не перезаписывает |
| `check <file.bpt>...` | обратимость `.bpt` → JSON → `.bpt` (сравнение `serialize` байт-в-байт) |
| `analyze <file.bpt\|file.json>... [--json]` | структура, привязки к порталу, проверки ссылок; код выхода `1` при ошибках |
| `compact <file.bpt\|file.json> [-o out.txt] [--json]` | только логика: дерево «одна строка на действие» — для чтения человеком или моделью |

Общий ключ `--charset=windows-1251` — для шаблонов с портала не в UTF-8 (старая коробка): строки
переводятся в UTF-8 при разборе и обратно при сборке.

```bash
php tools/bpt/bpt.php analyze ~/Downloads/bp-*.bpt
php tools/bpt/bpt.php decode ~/Downloads/bp-154.bpt -o /tmp/bp-154.bpt.json
php tools/bpt/bpt.php encode /tmp/bp-154.bpt.json -o /tmp/bp-154.bpt --force
php tools/bpt/bpt.php compact ~/Downloads/bp-154.bpt
```

## Что проверяет `analyze`

**Ошибки** (код выхода 1):
- повторяющиеся имена действий (`Name`);
- ссылки `{=A…:…}` на действия, которых нет в шаблоне (удалённые шаги — в выражение, скорее всего,
  подставляется пустое значение);
- `{=Variable:…}`, `{=Constant:…}`, `{=Template:…}` и условия `propertyvariablecondition` по
  необъявленным переменным/константам/параметрам;
- запрещённые действия (`CodeActivity` — PHP-код).

**Предупреждения:**
- поля документа из выражений, условий и `SetFieldActivity`, которых нет в `DOCUMENT_FIELDS`;
- ожидания (утверждение, ознакомление, запрос информации) без таймаута;
- циклы `WhileActivity`.

**Привязки к порталу** (ищутся только в логике, не в `DOCUMENT_FIELDS`): `user_N`, `group_*N`,
пользовательские поля `UF_*`, `DYNAMIC_N`, `PARENT_ID_N`, стадии `DTn_m:…`/`Cn:…`, `iblock_N`,
глобальные константы/переменные, URL, e-mail, «голые» числовые ID в пользовательских свойствах.
Их нужно заменить или сопоставить при переносе — см.
[antipattern-bizproc-hardcoded-portal-ids](../../wiki/cross-cutting/antipatterns/antipattern-bizproc-hardcoded-portal-ids.md).

## Ограничения

- Формат `.bpt` не документирован; утилита проверена на экспортах облака (`VERSION` 2, 11 шаблонов
  роботов смарт-процессов, 2026-09). Режим `--charset` проверен на синтетическом файле.
- Поиск привязок и проверки — эвристики: нет замечаний ≠ шаблон переносим. Смысловые ошибки (не та
  ветка, не тот согласующий) утилита не видит.
- `compact` — **с потерями**: удаляет `DOCUMENT_FIELDS`, пустые значения и служебные ключи. Для
  `encode` используйте только JSON из `decode`.
- Коды выхода: `0` — успех, `1` — ошибка обработки или ошибки в шаблоне, `2` — неверные аргументы.

## Безопасность и конфиденциальность

- Разбор только через `unserialize(..., ['allowed_classes' => false])`; файл с сериализованным
  объектом отклоняется.
- Шаблоны клиентов содержат их логику, ID сотрудников и адрес портала. `*.bpt` и `*.bpt.json`
  исключены из git (`.gitignore`); в репозиторий — только обезличенные примеры.
