# bpt.php — утилита для шаблонов бизнес-процессов (.bpt)

Разбор, сборка, проверка и генерация шаблонов БП Bitrix24. Формат файла описан в вики:
[concept-bizproc-bpt-format](../../wiki/modules/bizproc/concept-bizproc-bpt-format.md); формат
спецификации процесса — в [SPEC.md](SPEC.md); принятые решения — в [DESIGN.md](DESIGN.md).

**Требования:** PHP ≥ 8.1 с расширениями `zlib`, `json`, `mbstring`; для спецификаций в YAML —
расширение `yaml` (без него спецификации читаются и пишутся в JSON). Запуск — из корня репозитория.

## Команды

| Команда | Что делает |
|---------|-----------|
| `catalog [Тип\|алиас] [--json]` | каталог действий: таблица целиком или подробности одного типа |
| `compile <spec> -o <out.bpt>` | спецификация → `.bpt`; при ошибках файл не пишется |
| `decompile <file.bpt>` | `.bpt` → спецификация (библиотека примеров, сверка «туда-обратно») |
| `render <file.bpt\|spec>` | схема процесса в Mermaid для ревью |
| `snapshot <file.bpt>` | снимок портала: поля и стадии из `DOCUMENT_FIELDS` |
| `analyze <file.bpt>...` | структура, привязки к порталу, проверки ссылок; код выхода 1 при ошибках |
| `decode` / `encode` | `.bpt` ↔ JSON **без потерь** |
| `check <file.bpt>...` | обратимость `.bpt` → JSON → `.bpt` (сравнение байт-в-байт) |
| `compact <file.bpt>` | только логика: дерево «одна строка на действие» — для чтения и для модели |

Ключи: `-o <файл>` (по умолчанию вывод в stdout), `--json`, `--force` (перезапись),
`--portal=<снимок>` (плейсхолдеры `{{вид:Название}}`), `--strict` («сырые» ID портала в
спецификации — ошибка), `--keep-names` (сохранить имена действий при разборе),
`--charset=windows-1251` (портал не в UTF-8).

```bash
php tools/bpt/bpt.php analyze ~/Downloads/bp-*.bpt
php tools/bpt/bpt.php snapshot ~/Downloads/bp-154.bpt -o my.portal.yaml
php tools/bpt/bpt.php compile tools/bpt/examples/invoice-approval.bizproc.yaml \
    --portal=tools/bpt/examples/example.portal.yaml -o /tmp/invoice.bpt
php tools/bpt/bpt.php render /tmp/invoice.bpt -o /tmp/invoice.md
```

## Что проверяет `analyze`

**Ошибки** (код выхода 1): повторяющиеся имена действий; ссылки `{=A…:…}` на действия, которых нет
в шаблоне (удалённые шаги — в выражение, скорее всего, подставляется пустое значение); обращения к
необъявленным переменным, константам и параметрам; запрещённые действия (`CodeActivity` — PHP-код).

**Предупреждения:** поля документа, которых нет в `DOCUMENT_FIELDS`; ожидания (утверждение,
ознакомление, запрос информации) без таймаута; циклы `WhileActivity`.

**Привязки к порталу** — только в логике, не в `DOCUMENT_FIELDS`: `user_N`, `group_*N`, поля `UF_*`,
`DYNAMIC_N`, `PARENT_ID_N`, стадии `DTn_m:…`/`Cn:…`, `iblock_N`, глобальные константы, URL, e-mail,
«голые» числовые ID в пользовательских свойствах и свойства-идентификаторы из каталога
(`TemplateId`, `DynamicTypeId`). Их нужно сопоставить при переносе — см.
[antipattern-bizproc-hardcoded-portal-ids](../../wiki/cross-cutting/antipatterns/antipattern-bizproc-hardcoded-portal-ids.md).

## Устройство

```
bpt.php              разбор аргументов и вывод
src/BptFile.php      чтение и запись .bpt, JSON, кодировки
src/Analyzer.php     проверки и привязки к порталу
src/Catalog.php      каталог действий: свойства, значения по умолчанию, вложенность
src/SpecReader.php   спецификации: YAML и JSON
src/Compiler.php     спецификация → дерево → .bpt
src/Decompiler.php   .bpt → спецификация
src/Snapshot.php     снимок портала и плейсхолдеры
src/Mermaid.php      схема процесса
catalog/activities.php  данные каталога (25 типов)
examples/            синтетические пример спецификации и снимок
tests/               тесты
```

## Тесты

```bash
php tools/bpt/tests/run.php                                  # только синтетика
php tools/bpt/tests/run.php --corpus="C:/путь/к/экспортам"   # плюс сверка на реальных файлах
php tools/bpt/tests/run.php --filter=Каталог                 # часть тестов
```

Сверка на корпусе проверяет, что каталог покрывает все типы и свойства, что разбор и обратная
сборка воспроизводят каждый файл по смыслу (в том числе через снимок) и что схема строится.

## Ограничения

- Формат `.bpt` не документирован; каталог собран по корпусу из 14 экспортов облака
  (`VERSION` 2, роботы смарт-процессов, 2026-09). Новые типы добавляются по мере появления экспортов.
- Проверки — эвристики: «замечаний нет» ≠ «шаблон переносим». Смысловые ошибки (не та ветка, не тот
  согласующий) утилита не видит — для этого схема, ревью и тестовый портал.
- `compact` — **с потерями**: убирает `DOCUMENT_FIELDS`, пустые значения и служебные ключи. Для
  `encode` годится только JSON из `decode`.
- Процессы со статусами (`StateMachineWorkflowActivity`) не поддерживаются.
- Коды выхода: `0` — успех, `1` — ошибка обработки или ошибки в шаблоне, `2` — неверные аргументы.

## Безопасность и конфиденциальность

- Разбор только через `unserialize(..., ['allowed_classes' => false])`; файл с сериализованным
  объектом отклоняется. Строки не в UTF-8 — понятная ошибка с подсказкой про `--charset`.
- Шаблоны и снимки содержат данные клиента: `*.bpt`, `*.bpt.json`, `*.portal.yaml`, `*.portal.json`
  исключены из git. В репозиторий — только обезличенные примеры.
