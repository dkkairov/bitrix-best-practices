# Формат спецификации процесса (версия 1)

Спецификация — это YAML или JSON, из которого `bpt.php compile` собирает `.bpt`. Язык повторяет
Bitrix один в один: шаги называются алиасами действий, свойства — их настоящими именами из каталога
(`bpt.php catalog`). Всё, чего нет в спецификации, сборщик берёт из каталога.

```bash
php tools/bpt/bpt.php compile spec.yaml --portal=portal.yaml -o process.bpt
php tools/bpt/bpt.php render spec.yaml            # схема для ревью
php tools/bpt/bpt.php decompile process.bpt       # обратно в спецификацию
```

## Структура файла

```yaml
bizproc: 1                     # версия формата
name: Согласование счёта       # имя процесса (в .bpt не пишется, задаётся при загрузке)
document: DYNAMIC_1000         # тип документа: подсказка, в .bpt не пишется
# root_title: …                # заголовок корня; по умолчанию «Bizproc Automation template», как у
                               # нового шаблона в дизайнере. Нужен только старым шаблонам (decompile)
parameters: {}                 # параметры запуска
variables:                     # переменные шаблона
  amount: {Name: Сумма к оплате, Type: double, Required: true}
constants: {}                  # константы шаблона
steps:                         # последовательность шагов
  - <шаг>
```

`parameters`, `variables` и `constants` — объекты «код → описание поля»:
`{Name, Title, Description, Type, Required, Multiple, Default, Options}`.

## Шаг

Шаг — объект с **одним** ключом: алиас действия (`change_stage`) или его тип
(`CrmChangeStatusActivity`). Значение — служебные ключи вместе со свойствами Bitrix.

```yaml
- set_field:
    title: Зафиксировать сумму          # служебный ключ
    FieldValue:                          # свойство действия
      "{{field:Сумма к оплате}}": "{=Variable:amount}"
```

| Служебный ключ | Смысл |
|----------------|-------|
| `id` | логическое имя шага, чтобы на него ссылаться |
| `title` | заголовок действия; без него берётся заголовок по умолчанию из каталога |
| `off: true` | действие отключено (в дизайнере — серое) |
| `comment` | комментарий разработчика (`EditorComment`) |
| `name` | настоящее имя действия `A…`; нужно только для точной сверки «туда-обратно» |
| `raw` | свойства вне каталога: передаются как есть, сборщик предупреждает |
| `on_yes`, `on_no` | ветки действий с двумя исходами |
| `steps`, `branches`, `when`, `else` | структура (ниже) |

## Структурные шаги

```yaml
- if:                                     # условие
    title: Сумма заполнена?
    branches:
      - title: Да
        when: {fieldcondition: [["{{field:Сумма к оплате}}", "!empty", "", "0"]]}
        steps: [...]
      - title: Иначе
        else: true                        # ветка «иначе»
        steps: [...]

- parallel:                               # параллельное выполнение, минимум две ветки
    branches:
      - [...шаги...]                      # ветка — список шагов
      - {title: Своя ветка, steps: [...]} # или объект со своим заголовком

- while:                                  # цикл
    when: {fieldcondition: [["{{field:Готово}}", "empty", "", "0"]]}
    steps: [...]

- block: {title: Согласование, steps: [...]}   # блок действий (группировка)

- approve:                                # задание с двумя исходами
    id: fin
    Users: ["{{group:Бухгалтерия}}"]
    Name: Согласуйте счёт
    on_yes: [...]
    on_no: [...]
```

Какие действия что допускают, показывает `bpt.php catalog <Тип>` — поле «вложенность»:

| Вложенность | Что можно |
|-------------|-----------|
| `leaf`, `waiting` | ничего |
| `waiting-branches` | `on_yes`, `on_no` |
| `ifelse` | `branches` с условиями |
| `parallel` | `branches` (минимум две) |
| `loop` | `when` и `steps` |
| `block` | `steps` |

## Условия

Пишутся как в Bitrix; связка `"0"` — «и», `"1"` — «или» (наблюдение по корпусу).

| Ключ | Формат | Пример |
|------|--------|--------|
| `fieldcondition` | `[[поле, оператор, значение, связка]]` | `[["{{field:Сумма}}", "!empty", "", "0"]]` |
| `propertyvariablecondition` | то же, по параметрам и переменным | `[["approved", "=", "Y", "0"]]` |
| `mixedcondition` | объекты | `[{object: Document, field: TITLE, operator: "!empty", value: "", joiner: "0"}]` |
| `else: true` | ветка «иначе» | — |

## Выражения, ссылки, плейсхолдеры

- Выражения Bitrix пишутся как есть: `{=Document:TITLE > friendly}`, `{=Variable:amount}`,
  `{=Constant:link}`, `{=Template:param}`, `{=System:Now}`, формулы `=workdateadd(...)`.
- **Ссылка на результат шага:** `{=@id:Результат}` — сборщик подставит имя действия. Какие
  результаты бывают, видно в каталоге (`returns`): у утверждения — `Comments`, `LastApprover`,
  у запроса информации — `Comments`, `InfoUser`.
- **Плейсхолдеры портала:** `{{field|stage|user|group|smart|template:Название}}`. Работают внутри
  строк и в ключах отображений. Значения берутся из снимка (`--portal`):

```yaml
fields:    {"Сумма к оплате": UF_CRM_7_1700000000001}
stages:    {"Общая/Клиент": "DT1000_10:CLIENT"}
users:     {"Иванов Иван": user_42}
groups:    {"Бухгалтерия": group_g7}
```

Снимок с полями и стадиями делается из любого экспорта: `bpt.php snapshot file.bpt`. Людей, группы,
смарт-процессы и шаблоны пока вписывают вручную. Снимки содержат данные клиента и в git не попадают.

## Ловушки YAML

YAML 1.1 считает `Y`, `N`, `yes`, `on` булевыми значениями, а Bitrix хранит строки. Сборщик
приводит значения обратно:

| В спецификации | В шаблоне |
|----------------|-----------|
| `true` / `false` в свойстве | `"Y"` / `"N"` |
| `true` / `false` в `Required`, `Multiple` | `"1"` / `"0"` |
| число `50` | строка `"50"` |

Если значение важно сохранить буквально — берите его в кавычки: `MessageType: "4"`.

## Что проверяется при сборке

**Ошибки** (файл не пишется):
- неизвестный тип действия или свойство (каталог закрытый; обход — через `raw`);
- нет обязательного свойства;
- нарушена вложенность: `on_yes` у простого действия, `if` с одной веткой, `while` без `when`,
  `when` вместе с `else`;
- повтор `id`, ссылка `{=@id:…}` на несуществующий шаг;
- плейсхолдер не найден в снимке или найден неоднозначно;
- висячие ссылки, необъявленные переменные, константы и параметры;
- действие «PHP-код» — генерировать запрещено.

**Предупреждения:** неизвестный результат в ссылке, свойства через `raw`, «сырые» ID портала в
спецификации (с `--strict` — ошибка), ожидания без таймаута, циклы, пустое `DOCUMENT_FIELDS`.

## Чего пока нет

- Процессы со статусами (`StateMachineWorkflowActivity`) — только последовательные.
- Загрузка собранного файла на портал не проверена, в том числе с пустым `DOCUMENT_FIELDS`.
  Корень сверен с экспортом пустого шаблона из дизайнера (2026-09-21).
- Шаблон роботов по `.bpt` от шаблона дизайнера не отличить: ключ `kind` из версии 1 убран,
  сборщик только предупреждает о нём.
