# Исследование платформы Bitrix24

**TL;DR:** документация неполна и отстаёт, поэтому умение самому найти ответ в исходниках — не
«продвинутый уровень», а базовая гигиена разработчика под коробку.

## Почему важно при внедрении

Большая часть эмпирических находок в этой вики получена именно так: имя события, реальный
`ENTITY_ID` пользовательского поля, настоящее имя класса-фабрики. Отсюда же требование иметь
Linux и `grep` в рабочем окружении ([[checklist-dev-environment-and-git]]) — без них исследовать
платформу нечем.

## Приём 1 — через модуль REST

**Когда:** механизм доступен публично, и есть подозрение, что у него есть REST-метод.

Найти подписки на событие `onRestServiceBuildDescription` — это список классов, регистрирующих
REST-методы. Дальше идти по коду от регистрации к реализации.

```php
// из консольного PHP с подключённым ядром
print_r(\GetModuleEvents('rest', 'onRestServiceBuildDescription', true));
```

## Приём 2 — через кодовое имя сущности

**Когда:** известно, с какой бизнес-сущностью работаем.

Платформа именует согласованно: за сущностью закреплено кодовое имя (`DEAL` для сделки), и оно
попадает во все связанные классы, таблицы и константы. Знание имени превращает исследование в
поисковый запрос — см. [[concept-bitrix-naming-conventions]].

## Приём 3 — `grep` по исходникам модулей

**Когда:** нужно найти конкретную строку — CSS-класс, языковую фразу, идентификатор, имя метода.

```bash
grep -rin 'DEAL' /home/bitrix/www/bitrix/modules/crm/lib/
```

Ключи: `-r` рекурсивно, `-i` без учёта регистра, `-l` только имена файлов, `-n` с номерами строк.
Каталог локализовать заранее — поиск по всему `/bitrix/modules/` долгий.

## Приём 4 — через JS-события публичной части

**Когда:** нужно повлиять на поведение страницы. Ожидание через `setTimeout` — антипаттерн.

JS-события публичной части не задокументированы, но проходят через `BX.onCustomEvent`:

1. Открыть DevTools, ввести `BX.onCustomEvent` без скобок — увидеть имена аргументов
   (`eventObject, eventName, eventParams, secureParams` или минифицированные — использовать **те,
   что у вас**).
2. Перейти к источнику метода, найти последнюю строку перед фактическим вызовом.
3. Поставить **logpoint** с выражением
   `{'eventObject': eventObject, 'eventName': eventName, 'eventParams': eventParams}`.
4. Все последующие события сыплются в консоль.

Тем же способом находят внутренние менеджеры UI — так найден реестр редактора карточки CRM
([[recipe-crm-card-editor-js-access]]) и менеджер таймлайна ([[pattern-crm-timeline-client-side]]).

## Какой приём когда

| Что известно | Приём |
|--------------|-------|
| Имя бизнес-сущности | 2 → 3 |
| Видимый артефакт на странице (CSS-класс, фраза) | 3 |
| Есть REST-метод | 1 |
| Динамическое поведение страницы | 4 |

## Дисциплина исследования

- На проде — **только чтение**. Диагностические скрипты, которые что-то меняют, запускаются
  на тест-стенде и помечаются как таковые.
- Консольный PHP с ядром — **от владельца сайта**, не от root: см.
  [[antipattern-cli-php-as-root]].
- Найденное фиксировать с версией модуля — платформа меняется, и без версии факт протухает молча.
