# Командная PHP-строка

**Что это:** страница административного раздела, на которой выполняется произвольный PHP-код в
контексте портала. Основной инструмент быстрой диагностики.

## Ключевые факты
| Поле | Значение |
|------|----------|
| Тип | инструмент админки |
| Модуль | `main` |
| Это **не** CLI | код выполняется в веб-запросе, со всеми его ограничениями |

## Типичное применение

Первый приём [[concept-platform-reverse-engineering|исследования платформы]] — посмотреть, кто
регистрирует REST-методы:

```php
var_dump(\GetModuleEvents('rest', 'onRestServiceBuildDescription'));
```

Так же удобно проверять, включён ли Universal API у сущности, какие стадии у типа, что вернёт
метод ядра на конкретных данных.

## Подводные камни

- **Это веб-запрос:** действуют лимиты времени выполнения и памяти, нет `$argv`, а долгий скрипт
  оборвётся по таймауту. Тяжёлое — только консолью.
- **Консоль и веб дают разные результаты.** Класс, загруженный в консольном скрипте вручную,
  может замаскировать ошибку автозагрузки, которая проявляется только в вебе — ровно так
  диагностируется [[antipattern-ajax-controller-lowercase-name|проблема с регистром контроллера]].
- **Выполняется от текущего пользователя портала.** Это преимущество перед консолью, где легко
  запустить PHP от root и испортить кэш ([[antipattern-cli-php-as-root]]).
- **На проде — только чтение.** Диагностический код, который что-то меняет, запускается на
  тест-стенде. Инструмент не спрашивает подтверждения и не умеет откатывать.

## Открытые вопросы
- Точный путь в админке и необходимые права (предположительно администраторские).
- Сохраняется ли история запусков.
