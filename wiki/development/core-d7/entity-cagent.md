# `CAgent`

**Что это:** управление агентами — записями таблицы `b_agent`, чей PHP-код исполняется по
расписанию. Старый C-API; D7-эквивалента в документации нет.

## Ключевые факты
| Поле | Значение |
|------|----------|
| Тип | класс со статическими методами |
| Модуль | `main` |
| Хранилище | `b_agent`, поле кода до 64 КБ |
| Исполнение | `eval`, код **обязан вернуть строку** |
| Точка запуска | фоновые работы после отдачи страницы ([[concept-request-lifecycle]]) |

## Создание

```php
\CAgent::AddAgent(
    "\\Vendor\\Module\\Agent::run();",   // код одной строкой, точка с запятой обязательна
    'vendor.module',                     // модуль
    'N',                                 // периодический ли
    86400                                // интервал, секунд
);
```

`AddAgent` проверяет дубли по паре «имя + пользователь»: повторный вызов не создаст второй агент,
а вернёт `false`. Низкоуровневый `CAgent::Add($arFields)` использовать не рекомендуется.

**Код агента пишется одной строкой — вызовом статического метода.** Логика живёт в классе, а не
в строке в базе: иначе её нельзя ни отладить, ни положить в репозиторий.

**Возврат обязателен:** пустая строка — не повторять, имя следующего агента — поставить его в
очередь.

## Обновление и удаление

| Метод | Что делает |
|---|---|
| `Update($agentId, $arFields)` | единственный способ изменить |
| `RemoveAgent($name, $module, $user_id)` | удалить по имени |
| `Delete($id)` | удалить по ID |
| `RemoveModuleAgents($module)` | удалить **все** агенты модуля — обязательный шаг в `DoUninstall` |

## Выборка: `GetList($arOrder, $arFilter)`

Только порядок и фильтр — ни пагинации, ни выбора полей, ни сложной логики.

| Ключ фильтра | Поведение |
|---|---|
| `ID`, `MODULE_ID`, `=NAME` | строгое сравнение |
| `NAME` | LIKE |
| `ACTIVE`, `IS_PERIOD` | `Y`/`N`; иное значение игнорируется |
| `USER_ID` | `> 0` — по пользователю; иначе — агенты с пустым пользователем |
| `LAST_EXEC` | дата в формате `CLang::GetDateFormat()` |
| `NEXT_EXEC` | дата в формате `FORMAT_DATETIME` |

## Подводные камни

- **`LAST_EXEC` и `NEXT_EXEC` принимают разные форматы дат.** В многосайтовой конфигурации форматы
  могут отличаться — легко получить пустую выборку вместо ошибки.
- **Пустая строка в ключе фильтра просто игнорируется** — условие исчезает, и вы получаете больше
  строк, чем ждали.
- **`RemoveModuleAgents` не вызывает `Delete` внутри** — это независимая реализация; свои побочные
  действия на удаление агента она не выполнит.
- Агент — не место для тяжёлых операций: см. [[pattern-agents-vs-cron]].
- Забыть снять агенты в `DoUninstall` — классический «мусор после удаления модуля»
  ([[recipe-module-structure-and-install]]).
