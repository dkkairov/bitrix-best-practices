# Numerator — нумерация документов

**Что это:** штатный механизм ядра для номеров документов — счетов, заказов, коммерческих
предложений, своих сущностей. Номер собирается по шаблону из генераторов, счётчик хранит ядро.

**Класс:** `Bitrix\Main\Numerator\Numerator`.

**Зачем помнить:** нумерация «своими руками» (`max(NUMBER) + 1`) даёт дубли при одновременной
записи и разъезжается при откате транзакции. Здесь эта задача уже решена.

## Типы и генераторы

Тип нумератора — строка, по которой его находят: `DOCUMENT`, `ORDER`, `CRM_QUOTE`, `CRM_INVOICE`
и свои.

| Генератор (`Main\Numerator\Generator`) | Плейсхолдер |
|---|---|
| `SequentNumberGenerator` | `{NUMBER}` — последовательный номер |
| `DateNumberGenerator` | `{DAY}`, `{MONTH}`, `{YEAR}` |
| `RandomNumberGenerator` | `{RANDOM}` |
| `PrefixNumberGenerator` | `{PREFIX}` — фиксированный текст |

Шаблон собирается из плейсхолдеров: `{PREFIX}__{YEAR}/{NUMBER}—{RANDOM}` → `DOC__2025/007—A3F9K2`.

## Основные методы

| Метод | Что делает |
|---|---|
| `Numerator::create()` | новый пустой нумератор |
| `Numerator::load($id)` | загрузить по идентификатору |
| `Numerator::getOneByType($type)` | первый нумератор типа |
| `Numerator::getListByType($type)` | все нумераторы типа |
| `setConfig($config)`, `update($id, $config)` | настройка генераторов |
| `save()` | сохранить |
| `getNext()`, `getNext($hash)` | выдать следующий номер |
| `previewNextNumber()` | показать, каким будет номер, не расходуя его |
| `setHash($hashable)` | независимые счётчики: объект реализует `Hashable` |
| `setDynamicConfig($config)` | контекст для генераторов |

**Хеш** — то, ради чего стоит брать нумератор: он даёт отдельные последовательности внутри одного
нумератора (например, своя нумерация по каждой компании или по каждому году).

## Как применяем

- Свой тип документа в смарт-процессе или модуле — заводим свой тип нумератора и берём номер при
  создании элемента ([[concept-crm-universal-api]]).
- Показать пользователю будущий номер в форме — `previewNextNumber()`, номер при этом не тратится.
- Номер храним в поле сущности: он нужен людям и в печатных формах, пересчитывать его на лету
  нельзя.

## Ловушки

- **Номер выдаётся один раз.** `getNext()` расходует значение; вызвали и не сохранили — в
  последовательности будет дырка. Для предпросмотра есть `previewNextNumber()`.
- **Транзакция не возвращает номер.** Откат отменит запись, но израсходованный счётчик не вернётся —
  дырки в нумерации это нормально, объяснять заказчику лучше заранее.
- **Сброс по годам — это конфигурация генератора даты плюс хеш**, а не ручное обнуление таблицы.
- **Формат согласуем с заказчиком до запуска**: менять шаблон, когда документы уже выпущены,
  означает две разные серии номеров в одной базе.
