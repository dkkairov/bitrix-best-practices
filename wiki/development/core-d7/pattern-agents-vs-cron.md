# Агенты или cron

## Проблема и контекст

Нужен повторяющийся фоновый PHP-код: рассылка, синхронизация, пересчёт. В коробке два штатных
способа — агенты Bitrix и системный cron. Вопрос всплывает на каждом проекте, поэтому решение
стоит принимать по таблице, а не по привычке.

## Сравнение

| Аспект | Агенты (`CAgent`) | cron-скрипт |
|---|---|---|
| Где живёт | таблица `b_agent` | расписание ОС (`crontab`) |
| Где выполняется | в фоновых работах после отдачи страницы | вне HTTP, отдельный процесс PHP |
| Точность времени | зависит от посещаемости (на хитах) либо от cron-крутилки | строгая, по расписанию ОС |
| Минимальный интервал | секунды | 1 минута |
| Контекст Bitrix | пайплайн страницы, но без `$USER` и `SITE_ID` | с нуля: константы + `prolog_before.php` |
| Тиражируемость | **переезжает вместе с модулем** | нужен доступ к ОС у клиента |
| Тяжёлые задачи | нет: блокировка и риск таймаута | да, можно `set_time_limit(0)` |
| Сложность настройки | низкая (вызов API) | средняя (SSH, права, владелец процесса) |

## Правила выбора

1. **Тяжёлая операция** (5+ секунд или много памяти) → **cron**.
2. **Тиражируемый модуль** (ставится на чужие порталы) → **агент**: на чужой установке cron не
   настроишь.
3. **Нужна точность до минуты и лучше** → **агент**: cron не умеет интервалы меньше минуты.
4. Всё остальное — вкусовщина. База: cron для проектной работы, агенты — только там, где логика
   обязана переехать вместе с модулем.

## Когда агент точно нельзя
- Авторизация пользователя внутри агента — отправит cookie случайному посетителю.
- Нужен гарантированно точный момент времени.
- Операция дольше ~5 секунд.

## Когда cron точно нельзя
- У клиента нет доступа к ОС (shared-хостинг).
- Интервал меньше минуты.
- Логика должна переехать вместе с модулем.

## Как реализовать

```php
// агент: раз в сутки
\CAgent::AddAgent('\\Vendor\\Module\\Agent::run();', 'vendor.module', 'N', 86400);
```

```bash
# cron: от владельца сайта, НЕ от root
*/5 * * * * bitrix /usr/bin/php -f /home/bitrix/www/local/tools/sync.php >> /var/log/sync.log 2>&1
```

Владелец процесса критичен: консольный PHP с ядром от root портит кэш портала —
[[antipattern-cli-php-as-root]].

## Последствия
- **Агенты:** ноль требований к инфраструктуре, но плавающее время запуска на малопосещаемых
  порталах и жёсткий потолок по длительности.
- **cron:** предсказуемость и отсутствие ограничений по времени ценой доступа к серверу и
  отдельной процедуры переноса при миграции портала.

## Открытые вопросы
- Интервалы между 1 секундой и 1 минутой на малопосещаемом портале: агент на хитах теряет
  точность, cron не умеет — чем закрывать.
- Гибрид «агенты, запускаемые внешним cron» (`cron_events.php`) — контракт и ограничения.
