# Отладка коробки: дампы, замеры, панель

**Результат:** видно, что реально пришло в переменную и куда ушло время, без «эхо в середину
вёрстки».

**Когда применять:** поведение на стенде расходится с ожиданием, а `var_dump` в шаблоне ломает
вёрстку или вообще не доходит до экрана (AJAX, агент, cron).

## Дамп переменной

```php
use Bitrix\Main\Diag\Debug;

Debug::dump($var, 'заказ');                  // на экран, структурой
Debug::dumpToFile($var, 'заказ');            // то же в файл
Debug::writeToFile($var, 'заказ', '/local/logs/debug.log');   // print_r в файл
```

> **Файл по умолчанию — `__bx_log.log` в корне сайта.** В исходнике путь собирается как
> `$_SERVER['DOCUMENT_ROOT'] . '/' . $fileName`, то есть лог **открыт по прямой ссылке** из
> интернета. Всегда передаём свой путь в закрытый каталог (`/local/logs/`) и не оставляем дампы на
> проде.

## Замер времени

```php
Debug::startTimeLabel('импорт');
// ... код ...
Debug::endTimeLabel('импорт');

print_r(Debug::getTimeLabels());   // все метки: сколько заняла каждая
```

Метки вкладываются: снаружи общий проход, внутри — этапы. Этого обычно достаточно, чтобы понять,
где именно уходит время, и уже потом лезть в SQL ([[recipe-slow-query-diagnostics]]).

## Панель отладки

Кнопка «Отладка» в административной панели показывает по текущей странице: суммарную статистику,
SQL-запросы, кэш, компоненты, время исполнения. Быстрый способ увидеть, что страница делает 300
запросов, — раньше, чем лезть в код.

## Что ещё под рукой

| Инструмент | Когда |
|---|---|
| `Diag\SqlTracker` через `Connection::startTracker()` | какие запросы и сколько шли ([[recipe-slow-query-diagnostics]]) |
| PSR-3-логгеры `Diag\FileLogger` и компания | постоянное логирование, а не разовая отладка ([[concept-d7-logging]]) |
| Командная PHP-строка в админке | быстрый вызов метода на живых данных ([[entity-admin-php-console]]) |
| Приёмы исследования платформы | когда непонятно, какой код вообще работает ([[concept-platform-reverse-engineering]]) |

## Правила

- **Дампы не уезжают в репозиторий.** `Debug::dump()` в коммите — это отладка, забытая в проде.
- **На проде включаем показ ошибок точечно** и выключаем сразу: текст ошибки раскрывает пути и
  структуру базы.
- **Лог-файлы закрываем от веб-сервера** — правило то же, что для логгеров.
- **Дамп больших объектов кладёт память.** Коллекция ORM целиком в `dump()` — лишние сотни мегабайт;
  дампим нужное поле.
