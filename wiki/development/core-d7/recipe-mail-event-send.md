# Письмо из кода: почтовое событие и шаблон

**Результат:** уведомление уходит по шаблону, который правит контент-менеджер, а не разработчик.

**Когда применять:** любое письмо от портала — уведомление о заявке, напоминание, отчёт. Отправлять
`mail()` напрямую из своего кода не нужно: пропадёт история, шаблон и настройки отправителя.

## Три сущности

| Что | Чем создаётся | Смысл |
|---|---|---|
| **тип почтового события** | `CEventType::Add()` | код события и список макросов с пояснениями |
| **почтовый шаблон** | `CEventMessage::Add()` | тема, тело, отправитель, получатель, сайт |
| **событие отправки** | `\Bitrix\Main\Mail\Event::send()` | конкретное письмо с данными |

На чистом портале Битрикс24 шаблонов уже **124** — прежде чем заводить свой, стоит посмотреть, нет
ли подходящего штатного.

## Завести тип и шаблон (обычно в установщике модуля)

```php
$eventType = new CEventType();
$eventType->Add([
    'LID' => 'ru',
    'EVENT_NAME' => 'VENDOR_REQUEST_CREATED',
    'NAME' => 'Создана заявка',
    'DESCRIPTION' => "#REQUEST_ID# - номер заявки\n#AUTHOR# - автор",
    'EVENT_TYPE' => 'email',
]);

$message = new CEventMessage();
$message->Add([
    'ACTIVE' => 'Y',
    'EVENT_NAME' => 'VENDOR_REQUEST_CREATED',
    'LID' => ['s1'],
    'EMAIL_FROM' => '#DEFAULT_EMAIL_FROM#',
    'EMAIL_TO' => '#AUTHOR_EMAIL#',
    'SUBJECT' => 'Заявка #REQUEST_ID# принята',
    'BODY_TYPE' => 'html',
    'MESSAGE' => '<p>Здравствуйте, #AUTHOR#!</p>',
]);
```

## Отправить

```php
use Bitrix\Main\Mail\Event;

Event::send([
    'EVENT_NAME' => 'VENDOR_REQUEST_CREATED',
    'LID' => 's1',
    'C_FIELDS' => [
        'REQUEST_ID' => $id,
        'AUTHOR' => $name,
        'AUTHOR_EMAIL' => $email,
    ],
    'FILE' => [$fileId],      // вложения: ID файлов или абсолютные пути
]);
```

`Event::send()` кладёт письмо в очередь (таблица `b_event`) — реальная отправка идёт в конце хита
или по cron. Нужно отправить прямо сейчас (и дождаться результата) — `Event::sendImmediate()`.
Старый `CEvent::Send()` работает, но в новом коде берём `Main\Mail\Event`.

## Макросы

Пользовательские — те, что передали в `C_FIELDS`, в тексте пишутся как `#REQUEST_ID#`. Системные:
`#DEFAULT_EMAIL_FROM#`, `#SITE_NAME#`, `#SERVER_NAME#`.

Список макросов обязательно описываем в `DESCRIPTION` типа события: именно его видит человек,
который потом правит шаблон.

## Подводные камни

- **Письмо ушло в очередь ≠ письмо доставлено.** Результат отправки — в поле `SUCCESS_EXEC` записи
  очереди; при проблемах смотрим туда и в лог ([[concept-d7-logging]]).
- **Очередь разбирается на хитах или по cron.** На портале без посетителей письма ждут: для
  надёжности агенты и почта должны идти через cron ([[pattern-agents-vs-cron]]).
- **`ONLY_EMAIL`** перенаправляет всю почту на один адрес — незаменимо на тестовой копии боевого
  портала, чтобы клиенты не получили тестовых писем. На нашем стенде константа не определена.
- **Тестовая копия с боевой базой разошлёт настоящие письма.** Это первое, что проверяем после
  восстановления копии ([[recipe-box-backup]]).
- **Кодировка заголовков** настраивается параметром `convert_mail_header`; кириллическая тема без
  него превращается в мусор у части почтовых клиентов.
- **Язык письма** берётся из шаблона и сайта, а не из интерфейса пользователя
  ([[concept-localization-lang-files]]).
