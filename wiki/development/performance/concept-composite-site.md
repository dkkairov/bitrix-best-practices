# Композитный сайт: что кэшируется и как вырезать динамику

**TL;DR:** композит отдаёт посетителю готовый HTML без запуска PHP, а личные данные подгружает
следом одним AJAX-запросом. Выигрыш большой, цена — страницу приходится честно делить на
статическую и динамическую части, иначе пользователь увидит чужое имя в шапке.

**Когда применять:** публичная часть сайта с большим потоком анонимных посетителей. Для портала
Bitrix24, где каждая страница персональная, смысла почти нет.

## Два режима

| Режим | Что делает | Кому |
|---|---|---|
| **Автокомпозит** | ядро само решает, что динамика | простые сайты, типовые решения |
| **Композит** | разметку динамических зон делает разработчик | проекты с кастомными шаблонами |

Включается в админке: **Настройки → Настройки продукта → Композитный сайт**. Перед включением
сбрасываем кэш компонентов, после — настраиваем веб-сервер: отдачу статического HTML берёт на себя
NGINX.

## Что попадает в кэш, а что нет

**Кэшируется:** GET-запросы, публичная часть, HTML без пользовательских данных.

**Не кэшируется:**
- POST-запросы и административный раздел `/bitrix/`;
- страницы с cookie `_NCC` или параметром `ncc=1`;
- страницы, где скрипт завершился через `die()`/`exit` (о том же говорит
  [[concept-deferred-functions-and-page-areas]]: после `die()` эпилог не отрабатывает);
- всё, что помечено `markNonCacheable()`.

## Динамические области

| Приём | Где применяется |
|---|---|
| `$this->createFrame()` | в шаблоне компонента — метод шаблона, самый частый случай |
| `$APPLICATION->startDynamicWithID($id)` / `finishDynamicWithID(...)` | произвольный кусок страницы вне компонента |
| `setAnimation(true)` | плавная подмена содержимого |
| `setAutoUpdate(false)` | не обновлять блок при каждом хите |
| `setBrowserStorage(true)` | хранить прошлое значение в localStorage браузера |
| `markNonCacheable()` | отменить композит для всей страницы |

JS-события вставки блоков: `onFrameDataReceivedBefore`, `onBeforeDynamicBlockUpdate`,
`onFrameDataReceived`, `onFrameDataRequestFail` — на них вешаем свою реакцию (перерисовать счётчик,
показать ошибку).

**Вложенные динамические зоны не поддерживаются** — зона либо есть, либо её нет.

## Что переписать в шаблонах

Серверные значения в статической части превращаются в JS:

| Было (PHP) | Стало (JS) |
|---|---|
| `bitrix_sessid_get()` | `BX.bitrix_sessid()` |
| `$USER->GetID()` | `BX.message('USER_ID')` |
| время сервера | `BX.message('SERVER_TIME')` |

`bitrix_sessid_post()` в композитной странице вернёт пустое значение — токен подставляет JS.

## Сброс кэша

```php
\Bitrix\Main\Composite\Page::getInstance()->deleteAll();
```

Ещё — кнопка в админке и `cron_html_pages.php <часы>` по расписанию.

> **Про `StaticHtmlCache`.** Документация показывает `StaticHtmlCache::getInstance()->deleteAll()`.
> На стенде такой класс существует только как **заглушка для IDE** в
> `main/lib/Composite/compatibility/aliases.php` с пометкой `@deprecated` и указанием на
> `\Bitrix\Main\Composite\Page`; в шапке файла прямо написано, что использовать эти определения в
> коде не нужно. В новом коде пишем `Composite\Page`.

## Типичные ошибки

- **Переменные данные в `<head>`** — ядро пересоберёт страницу, композит не включится.
- **Случайные идентификаторы** в разметке: каждый хит даёт новый HTML, кэш бесконечно обновляется.
- **Проверка cookie в PHP** в статической части — решение о содержимом принято до кэша.
- **Разный HTML для разных браузеров** (`$_SERVER['HTTP_USER_AGENT']`) — то же самое.
- **Не все динамические зоны размечены** — самый неприятный случай: посетитель видит имя
  предыдущего пользователя.

## Как убедиться, что работает

- кнопка «Быстро с 1С-Битрикс» в правом нижнем углу публичной части;
- заголовок ответа `X-Bitrix-Composite`;
- **Настройки → Композитный сайт → Страницы** — список закэшированных страниц.
