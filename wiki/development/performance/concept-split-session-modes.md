# Разделённая сессия: горячие и холодные данные

**TL;DR:** классическая PHP-сессия блокируется целиком: пока один запрос её держит, остальные
запросы того же пользователя ждут. Коробка умеет делить сессию на «горячую» часть (авторизация —
в зашифрованных cookie, без блокировки) и «холодную» (всё остальное — в обычном хранилище,
с блокировкой при первом обращении).

**Когда применять:** много параллельных запросов от одного пользователя — AJAX-интерфейсы, чат,
длинные опросы. Особенно заметно там, где часть запросов долгие.

## Что куда попадает

| Часть | Что в ней | Где хранится | Блокировка |
|---|---|---|---|
| **Горячая** (kernel) | аутентификация, авторизация, базовые функции ядра | зашифрованные cookie (симметричное шифрование) | нет — запросы идут параллельно |
| **Холодная** (general) | остальные данные `$_SESSION` | Redis, Memcache, БД или файлы | есть, начинается при первом обращении |

Смысл в том, что подавляющему большинству запросов нужна только авторизация. Она уезжает в cookie,
и блокировка не берётся вообще — до первого честного обращения к «холодным» данным.

## Включение

Секция `session` в `/bitrix/.settings.php`:

```php
'session' => ['value' => [
    'mode' => 'separated',
    'lifetime' => 14400,
    'handlers' => [
        'kernel'  => 'encrypted_cookies',
        'general' => ['type' => 'file'],   // или redis / memcache / database
    ],
]],
```

На стенде секции `session` нет вовсе — это и есть классический режим по умолчанию. Классы
разделённого режима в ядре присутствуют: `Bitrix\Main\Session\CompositeSessionManager`,
`KernelSession`, `SessionConfigurationResolver`, обработчики в `Session\Handlers`.

## О чём помнить

- **Поведение блокировки зависит от хранилища холодной части.** Файлы блокируют жёстко, Redis и
  Memcache — мягче; при переходе на разделённый режим меняем и хранилище, иначе половина выигрыша
  теряется.
- **Горячая часть ограничена размером cookie.** Писать туда свои данные нельзя — это область ядра.
- **Свой код, который трогает `$_SESSION` на каждом хите, съедает выигрыш**: первое же обращение
  берёт блокировку холодной части. Складывать в сессию счётчики и кэши — плохая идея.
- **В многосерверной схеме** холодная часть должна быть общей для узлов (Redis/БД), а не файловой
  ([[concept-box-scaling]]).
- **В консоли сессия ведёт себя иначе** — у каждого запуска она своя, состояние между запусками не
  сохраняется ([[recipe-cli-script-bootstrap]]).
