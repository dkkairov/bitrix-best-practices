# Многосайтовость: один домен и разные домены

**TL;DR:** одна коробка умеет обслуживать несколько сайтов. На одном домене это папки
(`example.ru/`, `example.ru/shop/`), на разных доменах — отдельные `DocumentRoot` с символическими
ссылками на общее ядро. Копировать `/bitrix/` во второй сайт нельзя: ломается обновление и
нарушается лицензия.

**Когда возникает:** у заказчика основной сайт и лендинг на другом домене, региональные версии,
разделение «сайт + магазин».

## Два способа

| Способ | Как устроено | Цена |
|---|---|---|
| **Один домен, разные папки** | общий `DocumentRoot`, сайты разложены по каталогам | проще всего; адреса вида `example.ru/shop/` |
| **Разные домены** | ядро лежит в каталоге первого сайта, у остальных свой `DocumentRoot` и **символические ссылки** на `/bitrix/`, `/upload/`, `/local/` | нужен доступ к конфигурации веб-сервера |

Сайт на хите определяется по **домену** и **папке сайта** (путь после домена). Не подошёл ни один —
открывается сайт по умолчанию.

## Что общее, а что своё

- **Общее:** ядро, модули, компоненты, пользователи (при сквозной авторизации).
- **Своё у каждого сайта:** разделы и страницы, заказы, налоги, `robots.txt`, `sitemap.xml`.
- **Настраивается:** инфоблоки, баннеры, опросы, типы цен — привязываются к одному сайту или
  нескольким.

Идентификатор сайта — `SITE_ID`; в агентах и консольных скриптах его задаём явно, иначе сайт не
определится ([[recipe-cli-script-bootstrap]]). Свой код инициализации для конкретного сайта кладут
в `/bitrix/php_interface/<site_id>/init.php`.

## Ограничения

- **Редакция «Старт» — максимум два сайта.** Дальше нужна старшая редакция.
- **`/bitrix/`, `/upload/`, `/local/` не копируем** — только симлинки. Копия означает второй
  экземпляр ядра: обновления разъедутся, лицензия нарушена ([[antipattern-box-core-modification]] —
  та же логика «не трогаем ядро»).
- **Права на статистику не делятся по сайтам** — администратор видит данные всех сайтов.
- **Кэш общий.** На общем хранилище разделяем сайты параметром `sid`
  ([[concept-box-caching]]).

## Что проверить при приёмке

1. Каждый домен открывает свой сайт, а не «сайт по умолчанию».
2. `robots.txt` и `sitemap.xml` свои у каждого сайта.
3. Почтовые шаблоны и события привязаны к нужному сайту — иначе письма уходят от чужого имени.
4. Симлинки на месте после выкладки: архиватор или `rsync` без `-l` превращает их в копии каталогов.

> веб-сервера для второго домена здесь не проверялась — страница по документации.
