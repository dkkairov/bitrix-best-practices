# Резервная копия коробки: снять и восстановить

**Результат:** есть проверенная копия сайта и понятный способ развернуть её обратно.

**Когда применять:** перед обновлением платформы и выкладкой крупной доработки
([[recipe-git-deploy-to-production]]), при переносе на другой хостинг, при подготовке тестовой
копии боевого портала.

## Куда складывать

| Место | Когда подходит |
|---|---|
| локально, `/bitrix/backup/` | быстрый снимок перед изменением |
| облако 1С-Битрикс (Yandex Object Storage / Amazon S3) | регулярные копии без своего хранилища; **одновременно не больше трёх копий** |
| стороннее облако через модуль | свои правила хранения |

## Что кладём в архив

`tar.gz` собирается из выбранного: база данных, ядро, файлы публичной части. Исключить можно
статистику, поисковые индексы и журналы — на больших сайтах это половина объёма.

## Как снимать

- **Из админки:** Настройки → Инструменты → Резервное копирование.
- **По расписанию:** облачный сервис (ничего не настраивать на сервере) либо cron, который и так
  раз в минуту дёргает `/bitrix/modules/main/tools/cron_events.php`.
- **С панели хостинга:** прямой запуск `/bitrix/modules/main/tools/backup.php`.

Важная настройка — размер части архива: шаг должен укладываться в таймаут веб-сервера (ориентир
документации — **30 секунд**, часть до ~100 МБ несжатых данных).

## Восстановление

1. Через админку: Настройки → Инструменты → Резервное копирование → Список копий.
2. Скриптом `restore.php` в корне сайта — им же разворачивают копию на чистом хостинге.

После восстановления:
- **удалить `restore.php`** — иначе любой желающий развернёт на сайте свой архив;
- сбросить авторизацию AD/LDAP и двухфакторную аутентификацию, если они были;
- проверить симлинки при многосайтовости ([[concept-multisite]]).

## Большой сайт

- `/upload` архивируем отдельно обычным `tar`, а в копию Битрикса не включаем.
- Временные файлы исключаем по маске, задаём предел размера отдельного файла.
- Компрессию отключаем — так быстрее, объём компенсируем хранилищем.

## Ловушки

- **Пароль архива нигде не хранится.** Забыли — копия бесполезна; кладём в менеджер паролей вместе
  с доступами к хостингу.
- **Копия, которую ни разу не разворачивали, — не копия.** Разворачиваем её на стенд
  ([[recipe-box-test-stand-docker]]) хотя бы раз, до того как она понадобится всерьёз.
- **Тестовая копия боевого портала содержит персональные данные** — к ней те же требования по
  доступу, что к продакшену.
