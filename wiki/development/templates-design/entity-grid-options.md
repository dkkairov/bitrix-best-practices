# `\Bitrix\Main\Grid\Options`

**Что это:** чтение пользовательской конфигурации грида. Прежнее имя — `CGridOptions`. Парный к
[[entity-filter-options|`UI\Filter\Options`]].

## Ключевые факты
| Поле | Значение |
|------|----------|
| Тип | класс |
| Модуль | `main` |
| Конструктор | единственный аргумент — `GRID_ID` |

```php
$gridOptions = new \Bitrix\Main\Grid\Options('MY_GRID');
```

## Методы

| Метод | Назначение |
|---|---|
| `getUsedColumns($defaultColumns = [])` | колонки из пресета пользователя; нет пресета — `$defaultColumns` |
| `GetVisibleColumns()` | то же, но без запасного значения — при отсутствии пресета **пустой массив** |
| `GetSorting($arParams = [])` | расчёт сортировки с учётом параметров, запроса, сессии и настроек пользователя |

```php
$sort = $gridOptions->GetSorting([
    'sort' => ['NAME' => 'ASC'],
    'vars' => ['by' => 'by', 'order' => 'order'],   // имена URL-параметров
]);
```

## Зачем это на самом деле: производительность

`getUsedColumns()` позволяет **не считать то, что пользователь не видит**. Документированный
случай: вычисляемые столбцы занимали 60 % времени генерации страницы, а нужны были меньше чем 1 %
пользователей. Проверка «эта колонка в пресете?» перед дорогим расчётом — самая дешёвая
оптимизация списка ([[checklist-box-performance]]).

Второй сценарий — экспорт «как видит пользователь»: набор и порядок столбцов берутся из его
пресета.

## Подводные камни

- **`GetVisibleColumns()` не имеет запасного значения** — у пользователя без пресета вы получите
  пустой список и, если не проверили, пустую таблицу. Предпочитайте `getUsedColumns()` с явным
  набором по умолчанию.
- **Несколько гридов на странице конфликтуют по `by` и `order`** — задавайте им разные имена
  через `vars`, иначе сортировка одного грида будет менять другой.
- Класс только читает: изменить настройки пользователя через него нельзя.
