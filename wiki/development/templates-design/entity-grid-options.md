# `\Bitrix\Main\Grid\Options`

**Что это:** пользовательская конфигурация грида. Прежнее имя — `CGridOptions`. Парный к
[[entity-filter-options|`UI\Filter\Options`]]
([Персональные настройки](https://bx24devbook.website.yandexcloud.net/Razrabotka/UI/Tablicy/Personalnye_nastrojki.html)).

> **Исправлено 2026-09-21 при сверке с книгой.** Было «класс только читает, изменить настройки
> нельзя» — методы изменения (`set*`, `save()`) у класса есть, книга их просто сознательно не
> разбирает. «60 % времени» — кейс автора книги про построение грида, а не «документированный случай»
> генерации страницы. Добавлен `GetNavParams()`. Атрибуция исправлена.

## Ключевые факты
| Поле | Значение |
|------|----------|
| Тип | класс |
| Модуль | `main` |
| Конструктор | единственный аргумент — `GRID_ID` |

```php
$gridOptions = new \Bitrix\Main\Grid\Options('MY_GRID');
```

## Методы

| Метод | Назначение |
|---|---|
| `getUsedColumns($defaultColumns = [])` | колонки из пресета пользователя; нет пресета — `$defaultColumns` |
| `GetVisibleColumns()` | то же, но без запасного значения — при отсутствии пресета **пустой массив** |
| `GetSorting($arParams = [])` | расчёт сортировки с учётом параметров, запроса, сессии и настроек пользователя |
| `GetNavParams(['nPageSize' => N])` | размер страницы (по умолчанию 20) для постраничной навигации |
| `set*`, `save()` | изменение настроек — существуют, но книга их не разбирает: редкий случай, поручать опытному разработчику |

```php
$sort = $gridOptions->GetSorting([
    'sort' => ['NAME' => 'ASC'],
    'vars' => ['by' => 'by', 'order' => 'order'],   // имена URL-параметров
]);
$nav = $gridOptions->GetNavParams(['nPageSize' => 20]);
```

## Зачем это на самом деле: производительность

`getUsedColumns()` позволяет **не считать то, что пользователь не видит**. Кейс автора книги: два
тяжёлых вычисляемых столбца занимали до 60 % времени построения грида, а пользовались ими меньше 1 %
сотрудников. Проверка «эта колонка в пресете?» перед дорогим расчётом — самая дешёвая оптимизация
списка ([[checklist-box-performance]]).

Второй сценарий — экспорт «как видит пользователь»: набор и порядок столбцов берутся из его
пресета.

## Подводные камни

- **`GetVisibleColumns()` не имеет запасного значения** — у пользователя без пресета вы получите
  пустой список и, если не проверили, пустую таблицу. Предпочитайте `getUsedColumns()` с явным
  набором по умолчанию.
- **Несколько гридов на странице конфликтуют по `by` и `order`** — задавайте им разные имена
  через `vars`, иначе возможна сортировка по несуществующему полю вплоть до фатальной ошибки.
