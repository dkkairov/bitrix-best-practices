# Оргструктура портала

**TL;DR:** подразделения и сотрудники — базовая опора прав доступа, отчётов и связей
«руководитель ↔ подчинённый». Ошибки в оргструктуре вылезают позже в правах и аналитике, поэтому
она настраивается в начале проекта, а не «когда дойдут руки» (вывод команды).

> **Сверено с «Книгой разработчика» 2026-09-21.** Атрибуция исправлена (материал — из
> [Организационной структуры](https://bx24devbook.website.yandexcloud.net/Modul_Intranet/Orgstruktura.html)
> книги). Уточнено: ID в `GetStructure()` — строки; `GetIBlockSectionChildren()` включает и исходные
> ID. Выводы про права и автоматизацию помечены как опыт команды. **Возможное устаревание:** книга
> (примеры ≈2023) описывает оргструктуру на инфоблоке, а в REST уже есть методы
> `humanresources.node.*` (отделы и команды) — см. «Облако vs коробка».

## Как устроено (по книге)

Подразделение — **раздел** служебного инфоблока «Оргструктура». Руководитель задаётся полем
`UF_HEAD` подразделения. Сотрудники — вторая единица структуры (пользователи портала, привязанные к
подразделениям).

- **один корень** оргструктуры на портал;
- инфоблок оргструктуры книга называет **единым** для всех сайтов установки, но в разделе API сама
  же показывает чтение его ID с учётом сайта — читайте опцию с `siteId`, это страховка для
  многосайтовых установок.

## Поля подразделения

**Базовые:** `ACTIVE`, `NAME`, `UF_HEAD` (ID руководителя строкой или `null`), `IBLOCK_SECTION_ID`
(вышестоящий раздел, `0` для корня).

**Учёт рабочего времени** (опционально): учёт времени, максимальное время начала дня, минимальное
время завершения и минимальная продолжительность дня, отчёт за день и его шаблоны, свободный график.

## Работа из кода (коробка)

Модуль `intranet` в публичной части подключён всегда, но книга советует всё равно проверять
`Loader::includeModule('intranet')` ([перед использованием API](https://bx24devbook.website.yandexcloud.net/Modul_Intranet/O_module.html#pered-ispol-zovaniem-api)).

```php
use Bitrix\Main\Config\Option;

$iblockId = Option::get('intranet', 'iblock_structure', '-1');           // общий
$forSite  = Option::get('intranet', 'iblock_structure', '-1', 'co1');    // для сайта
```

**Значение по умолчанию `-1`, а не `0` — намеренно.** В `getList` инфоблока нулевое значение
игнорируется: при технической ошибке запрос вернёт «всё подряд» вместо пустого результата.

| Метод | Что делает |
|---|---|
| `CIntranetUtils::GetStructure()` | всё дерево разом: `TREE` (родитель → дети) и `DATA` (id → детали); **все ID — строки** |
| `CIntranetUtils::GetIBlockSectionChildren($ids)` | исходные ID **плюс** все вложенные, плоским списком. Делает запросы в цикле; **ключам результата не доверять** |
| `CIntranetUtils::GetDeparmentsTree($id, $bFlat = false)` | дерево от одного подразделения; `$bFlat = true` — плоский массив (имя метода именно такое) |
| `\Bitrix\Intranet\Util::getDepartmentEmployees($params)` | сотрудники подразделения: `DEPARTMENTS`, `RECURSIVE` (по умолчанию `N`), `ACTIVE`, `SKIP`, `SELECT`; возвращает наследника `CDBResult` |

Одноимённый `CIntranetUtils::getDepartmentEmployees()` — прокси для совместимости, книга его не
рекомендует. Подробнее о методах — [[entity-cintranet-utils]].

## Почему важно при внедрении

- **Права доступа** можно выдавать на подразделения, а руководители видят отчёты и учёт времени
  подчинённых (книга). Кривое дерево даёт кривые права, которые потом чинят точечными исключениями
  ([[recipe-crm-permissions]]) — опыт команды.
- **Отчёты и представления** строятся по подразделениям.
- **Автоматизация** обращается к руководителю через `UF_HEAD`: если он не проставлен, согласование
  может уйти в никуда. Это стоит проверять в приёмке — [[checklist-portal-initial-setup]] (опыт
  команды, в книге этого нет).

## Облако vs коробка

Само понятие оргструктуры одинаково. Программный доступ через `CIntranetUtils` — коробка. В облаке —
REST: `department.get` (scope `department`,
[apidocs](https://apidocs.bitrix24.ru/api-reference/departments/department-get.html)) и новые методы
`humanresources.node.*` для отделов и команд (scope `humanresources`,
[apidocs](https://apidocs.bitrix24.ru/api-reference/departments/node/humanresources-node-get.html)) —
сверено через MCP 2026-09-21. Появление `humanresources` — признак, что в новых версиях структура
компании ведётся этим модулем: прежде чем писать в инфоблок оргструктуры напрямую на свежей коробке,
**проверить на стенде**, какая модель у вас.
