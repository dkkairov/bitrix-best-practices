# Оргструктура портала

**TL;DR:** подразделения и сотрудники — базовая опора прав доступа, отчётов и связей
«руководитель ↔ подчинённый». Ошибки в оргструктуре вылезают позже в правах и аналитике, поэтому
она настраивается в начале проекта, а не «когда дойдут руки».

## Как устроено

Подразделение — **раздел** служебного инфоблока «Оргструктура». Сотрудник — запись в `b_user`,
связанная с подразделением; руководитель задаётся полем `UF_HEAD` подразделения.

Ограничения, которые стоит знать заранее:

- **один корень** оргструктуры на портал;
- инфоблок оргструктуры **единый** для всех сайтов установки.

## Поля подразделения

**Базовые:** `ACTIVE`, `NAME`, `UF_HEAD` (ID руководителя или `null`), `IBLOCK_SECTION_ID`
(вышестоящий раздел, `0` для корня).

**Учёт рабочего времени** (опционально): учёт времени, максимальное и минимальное время начала и
завершения дня, минимальная продолжительность дня, отчёт за день и его шаблоны, свободный график.

## Работа из кода (коробка)

```php
use Bitrix\Main\Config\Option;

$iblockId = Option::get('intranet', 'iblock_structure', '-1');           // общий
$forSite  = Option::get('intranet', 'iblock_structure', '-1', 'co1');    // для сайта
```

**Значение по умолчанию `-1`, а не `0` — намеренно.** В `getList` инфоблока нулевое значение
игнорируется: при технической ошибке запрос вернёт «всё подряд» вместо пустого результата.

| Метод | Что делает |
|---|---|
| `CIntranetUtils::GetStructure()` | всё дерево разом: `TREE` (родитель → дети) и `DATA` (id → детали) |
| `CIntranetUtils::GetIBlockSectionChildren($ids)` | для списка ID — все потомки плоско. Делает запросы в цикле; **ключам результата не доверять** |
| `CIntranetUtils::GetDeparmentsTree($id, $bFlat = false)` | дерево от одного подразделения; `$bFlat = true` — плоский массив |
| `\Bitrix\Intranet\Util::getDepartmentEmployees($params)` | сотрудники подразделения: `DEPARTMENTS`, `RECURSIVE`, `ACTIVE`, `SKIP`, `SELECT` |

## Почему важно при внедрении

- **Права доступа** в CRM и задачах раздаются на подразделения и «подразделение и подчинённые» —
  кривое дерево даёт кривые права, которые потом чинят точечными исключениями
  ([[recipe-crm-permissions]]).
- **Отчёты и представления** строятся по подразделениям.
- **Автоматизация** обращается к руководителю через `UF_HEAD`: если он не проставлен, согласование
  молча уходит в никуда. Это стоит проверять в приёмке —
  [[checklist-portal-initial-setup]].

## Облако vs коробка

Само понятие и настройка оргструктуры — одинаковы. Программный доступ через `CIntranetUtils` —
коробка; в облаке те же данные доступны через REST (`department.*`, `user.get`).
