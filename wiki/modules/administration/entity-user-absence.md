# `\Bitrix\Intranet\UserAbsence`

**Что это:** D7-обёртка над графиком отсутствий — удобнее и быстрее, чем выбирать элементы
инфоблока напрямую.

## Ключевые факты
| Поле | Значение |
|------|----------|
| Тип | класс |
| Модуль | `intranet` |
| Хранение | инфоблок «График отсутствий» |
| Edition | box |

## Методы

| Метод | Что отдаёт |
|---|---|
| `getIblockId(): int` | ID инфоблока отсутствий текущего сайта |
| `getVacationTypes(): array` | типы отсутствий с метаданными |
| `getCurrentMonth(): array` | **кэшируемо** — отсутствия текущего месяца, `userId → idx → отсутствие` |

Поля одного отсутствия: `ID`, `USER_ID`, `ENTRY_TYPE` (символьный код), `ENTRY_TYPE_ID`,
`ENTRY_TYPE_VALUE` (название), `IS_VACATION`, `DATE_FROM_TS`, `DATE_TO_TS`.

Тип отсутствия: `ID` (символьный код, например `VACATION`), `ENUM_ID`, `NAME`, `ACTIVE`.

## Подводные камни

- **`ACTIVE` у типа отсутствия означает не «тип включён», а «это отпуск»** — признак, отделяющий
  отпуск от командировки и больничного. Имя поля прямо вводит в заблуждение.
- **`getIblockId()` может вернуть `0`** при повреждённых настройках. Ноль в фильтре `getList`
  инфоблока не сужает выборку, а обнуляет условие — и вы получите «всё подряд» вместо пустого
  результата. Проверяйте результат явно; для чтения опции руками используйте значение по умолчанию
  `-1`, а не `0` ([[entity-config-option]], [[concept-org-structure]]).
- **Своих событий на создание, изменение и удаление отсутствий нет** — подписываться нужно на
  события инфоблоков. Это же значит, что CRUD делается средствами инфоблока, а не через этот класс.
- `getCurrentMonth()` кэшируется: после ручной правки данных ждите отставания.
