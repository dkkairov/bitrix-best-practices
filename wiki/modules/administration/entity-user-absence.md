# `\Bitrix\Intranet\UserAbsence`

**Что это:** D7-класс для чтения графика отсутствий
([Отсутствия](https://bx24devbook.website.yandexcloud.net/Modul_Intranet/Otsutstvia.html)). Запись
отсутствий — средствами инфоблока, [[recipe-intranet-absence-import]].

> **Исправлено 2026-09-21 при сверке с книгой.** `getIblockId()` возвращает **общий** ID инфоблока
> отсутствий, а не «текущего сайта»; для сайта — опция с `siteId`. Добавлены структура элемента,
> события начала и окончания отсутствия и совет не заводить свои типы. Атрибуция исправлена.

## Ключевые факты
| Поле | Значение |
|------|----------|
| Тип | класс |
| Модуль | `intranet` |
| Хранение | инфоблок «График отсутствий» (по умолчанию в типе инфоблоков «Оргструктура»); вторая часть отсутствий — в модуле «Календарь» |
| ID инфоблока | опция `intranet` / `iblock_absence` — общая и для сайта; инфоблок может быть своим у каждого сайта |
| Edition | box |

## Элемент-отсутствие (инфоблок)

| Поле | Смысл |
|---|---|
| `USER` (свойство) | сотрудник |
| `ABSENCE_TYPE` (свойство-список) | тип отсутствия |
| `NAME` | причина |
| `ACTIVE_FROM` / `ACTIVE_TO` | период |

## Методы

| Метод | Что отдаёт |
|---|---|
| `getIblockId(): int` | **общий** ID инфоблока отсутствий; при повреждённых настройках может вернуть `0` |
| `getVacationTypes(): array` | типы отсутствий с метаданными |
| `getCurrentMonth(): array` | **кэшируемо** — отсутствия текущего месяца, `userId → idx → отсутствие` |

ID инфоблока для конкретного сайта:

```php
$iblockId = \Bitrix\Main\Config\Option::get('intranet', 'iblock_absence', '-1', $siteId);
```

Поля одного отсутствия в `getCurrentMonth()`: `ID`, `USER_ID`, `ENTRY_TYPE` (символьный код),
`ENTRY_TYPE_ID`, `ENTRY_TYPE_VALUE` (название), `IS_VACATION`, `DATE_FROM_TS`, `DATE_TO_TS`.

Тип отсутствия: `ID` (символьный код, например `VACATION`), `ENUM_ID`, `NAME`, `ACTIVE`.

## События

Своих событий на создание, изменение и удаление отсутствий нет — используют события инфоблоков. Есть
события **начала и окончания** отсутствия: `OnStartAbsence` / `OnEndAbsence` с параметрами
`USER_ID`, `ABSENCE_TYPE`, `START`, `END`, `DURATION` (в секундах); возвращаемое значение не
обрабатывается ([начало и окончание](https://bx24devbook.website.yandexcloud.net/Modul_Intranet/Otsutstvia.html#nacalo-i-okoncanie)).
**Проверить на стенде:** в примере книги обработчик подписан на модуль `'crm'`, хотя по тексту события
относятся к интранету; срабатывают ли они для всех типов отсутствий — тоже проверить. Типичные
применения — делегирование на время отпуска, уведомления, запуск процесса.

## Подводные камни

- **`ACTIVE` у типа отсутствия означает не «тип включён», а «это отпуск»** — признак, отделяющий
  отпуск от командировки и больничного. Имя поля прямо вводит в заблуждение.
- **`getIblockId()` может вернуть `0`** при повреждённых настройках. Ноль в фильтре `getList`
  инфоблока не сужает выборку, а обнуляет условие — и вы получите «всё подряд» вместо пустого
  результата. Проверяйте результат явно; для чтения опции руками используйте значение по умолчанию
  `-1`, а не `0` ([[entity-config-option]], [[concept-org-structure]]). ID инфоблока в коде не
  хардкодить.
- **Свои типы отсутствий книга добавлять не рекомендует** — не все подсистемы их распознают.
- `getCurrentMonth()` кэшируется: после ручной правки данных возможно отставание (гипотеза команды —
  как сбрасывается этот кэш, книга не описывает).
