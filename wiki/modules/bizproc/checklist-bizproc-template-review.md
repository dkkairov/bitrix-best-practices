# Ревью шаблона БП: ошибки проектирования

**Когда применять:** перед выкладкой нового или изменённого шаблона, при приёмке чужого шаблона и
при разборе «процесс висит / портал тормозит». Пункты собраны из урока курса
[«Распространенные ошибки»](https://dev.1c-bitrix.ru/learning/course/?COURSE_ID=57&LESSON_ID=8445),
уроков о действиях и кода ядра (bizproc 26.1075.0).

> **Черновик:** пункты взяты из курса и кода ядра; как единый чек-лист на проекте ещё не применялся.

## Предусловия
- Шаблон есть в файле: экспорт из дизайнера (`bp-<ID>.bpt`) или сборка из спецификации.
- Есть тестовый портал, где процесс можно прогнать по всем веткам.

## Чек-лист

### Ожидания и выход из них
- [ ] У каждого задания («Утверждение», «Ознакомление», «Запрос информации») задан срок — или его
  отсутствие осознанно: без срока процесс ждёт исполнителя сколько угодно. Известно, что будет по
  истечении: утверждение — автоматическое отклонение и ветка «нет»; ознакомление и запрос — задание
  закрывается, процесс идёт дальше; запрос с отклонением — ветка отказа
  ([[concept-bizproc-activity-catalog|каталог действий]]).
- [ ] Срок не меньше «Минимального времени ожидания для действий» (облако — 5 минут): меньший ядро
  поднимет до минимума.
- [ ] В «Параллельном ожидании действия» есть ветка с «Паузой в выполнении» — иначе, если никто не
  нажал команду, процесс висит
  ([урок 3790](https://dev.1c-bitrix.ru/learning/course/?COURSE_ID=57&LESSON_ID=3790)).
- [ ] «Ожидание стадии сделки» и «Ожидание статуса лида» (срока у них нет) стоят только в шаблонах с
  запуском при создании ([урок 7399](https://dev.1c-bitrix.ru/learning/course/?COURSE_ID=57&LESSON_ID=7399)).
- [ ] События ждут специальным действием, а не циклом с паузой, который опрашивает статус (урок 8445).

### Циклы и ветвления
- [ ] У «Цикла» есть аварийный выход — по счётчику или времени, а не только по «правильному» условию;
  тело не пустое. Предел — 1000 итераций (в коробке — настройка модуля).
- [ ] У «Условия» есть ветка «иначе» (условие «Истина»), если нужна реакция на «ничего не подошло»: без
  неё конструкция просто пропускается.
- [ ] Связка «или» не стоит в первой строке условия — тогда условие истинно всегда (код ядра;
  `tools/bpt` предупреждает). «Не равно» для нескольких значений собирают через «и»: с «или» оно всегда
  истинно ([урок 3789](https://dev.1c-bitrix.ru/learning/course/?COURSE_ID=57&LESSON_ID=3789)).
- [ ] «Сменить стадию» и «Сменить воронку» — последний шаг ветки: первое завершает процесс, второе
  останавливает все процессы элемента
  ([урок 9011](https://dev.1c-bitrix.ru/learning/course/?COURSE_ID=57&LESSON_ID=9011),
  [урок 20826](https://dev.1c-bitrix.ru/learning/course/?COURSE_ID=57&LESSON_ID=20826)).
- [ ] «Запустить бизнес-процесс» не запускает свой же шаблон (заблокировано ядром), тип документа
  совпадает с типом шаблона, «Ожидать завершения» выбрано осознанно.

### Автозапуск и нагрузка
- [ ] Процесс «при изменении» без пауз, заданий и ожиданий — он должен сразу отработать: пока ждёт,
  документ меняют снова и запускаются новые экземпляры (урок 8445, стенд).
- [ ] Учтён лимит одновременных процессов на документ (облако — 2, коробка — настройка): сверх лимита
  новый процесс не стартует, а автозапуск «при изменении» легко его выбирает.
- [ ] Поля документа меняются одним «Изменением документа», а не несколькими подряд. Выражение,
  зависящее от поля из того же действия, увидит старое значение — считать в переменную
  ([урок 5359](https://dev.1c-bitrix.ru/learning/course/?COURSE_ID=57&LESSON_ID=5359)).

### Данные, ссылки, выражения
- [ ] Нет ссылок `{=A…:Результат}` на удалённые или выключенные шаги: `php tools/bpt/bpt.php analyze`
  показывает висячие ссылки.
- [ ] Одинаковые действия подписаны разными заголовками: в «Вставке значения» результаты
  сгруппированы по заголовку.
- [ ] Выражения проверены прогоном: ошибка синтаксиса не останавливает процесс, выражение просто
  выводится текстом ([[concept-bizproc-expressions|выражения]]).
- [ ] «Кто запустил» — `{=Template:TargetUser}`, а не `{=User:ID}`: после паузы или на агенте текущий
  пользователь может быть любым.
- [ ] Отправитель уведомления на ветке «нет» не берётся из «Последнего голосовавшего», если срок может
  истечь: при автоматическом отклонении никто не голосовал и результат пуст (вывод по коду ядра). Берут
  константу или тип «Уведомление от системы».
- [ ] Код группы не стоит в поле для одного пользователя, если так не задумано: подставится её
  пользователь с наименьшим ID.

### Роли, права, перенос
- [ ] Роли — в константах, переменных или полях документа, а не конкретные сотрудники; ссылки без
  адреса портала ([[antipattern-bizproc-hardcoded-portal-ids|зашитые ID портала]]).
- [ ] Тип делегирования выбран осознанно: «только подчинённым», «всем сотрудникам» или «никому».
- [ ] Конфиденциальный текст задания — с «Ограничить доступ».
- [ ] Нет действия «PHP код» ([[antipattern-bizproc-php-code-activity|антипаттерн]]).
- [ ] Если после своего действия процесс должен остановиться при ошибке, действие отдаёт признак
  ошибки результатом, а шаблон проверяет его условием и ставит «Прерывание процесса». Ни ошибка, ни
  исключение действия процесс не останавливают, а фатальная ошибка PHP его вешает (стенд;
  [[recipe-bizproc-custom-activity-baseactivity|своё действие]]).

### Проверка
- [ ] `php tools/bpt/bpt.php analyze <файл.bpt>` без ошибок, предупреждения разобраны.
- [ ] Прогон на тестовом портале: обе ветки каждого задания, истечение срока, повторный запуск на том
  же документе; журнал включён ([[recipe-bizproc-debugging|отладка]]).

## Критерии приёмки
- Процесс нельзя «повесить» бездействием людей: у каждого ожидания есть срок или ветка-таймаут.
- Повторный запуск на том же документе не плодит зависшие экземпляры.
- Шаблон переносится на другой портал заменой констант и таблицы соответствия стадий и полей.
