# `GlobalsManager` — глобальные переменные и константы

**Что это:** API глобальных переменных и констант бизнес-процессов
([глобальные хранилища](https://bx24devbook.website.yandexcloud.net/Modul_Biznes_processy/Dejstvia/Okruzenie.html#global-nye-hranilisa)).
Практический смысл — держать общие для портала значения (ID ответственного отдела, пороги сумм)
**вне шаблонов**, а не вписывать их в каждый процесс (практика команды).

> **Уточнено 2026-09-21 при сверке с книгой.** Книга описывает класс, видимость и четыре метода; тезисы
> о переносимости шаблонов и о поиске глобала по имени — наши, они помечены. Значение хранится в
> ключе `Default` описания; из активити глобалы читаются через `getRuntimeProperty(SourceType::GlobalVariable | GlobalConstant, …)`.

## Ключевые факты
| Поле | Значение |
|------|----------|
| Тип | абстрактный класс `\Bitrix\Bizproc\Workflow\Type\GlobalsManager` |
| Наследники | `GlobalVar` (переменные), `GlobalConst` (константы) |
| Модуль | `bizproc` |
| Привязка | к **типу документа**: `['crm', 'CCrmDocumentDeal', 'DEAL']` |

Все методы живут в родительском классе, наследники различаются только семантикой.

## Методы

| Метод | Что делает |
|---|---|
| `getAll($documentType): array` | все глобалы для типа документа |
| `getById($id): ?array` | описание одного |
| `upsert($id, array $property, $userId = null): bool` | создать или обновить |
| `delete($id): bool` | удалить |

Описание глобала: `Name`, `Description`, `Type`, `Required`, `Multiple`, `Options`, `Default`,
`Visibility`, `CreatedBy` / `CreatedDate`, `ModifiedBy` / `ModifiedDate`.

## Видимость

| `Visibility` | В интерфейсе | Где доступно |
|---|---|---|
| `GLOBAL` | «Везде» | везде; в «Управлении сайтом» есть только этот вариант |
| `<module>` | «CRM» | только в модуле, например `CRM` |
| `<module>_<entity>` | «[Сущность CRM]» | только в сущности, например `CRM_COMPANY`; в выборе — сущность, для которой открыт шаблон |

Подписи — по курсу ([урок 23718](https://dev.1c-bitrix.ru/learning/course/?COURSE_ID=57&LESSON_ID=23718)).

## В интерфейсе
- Кнопки «Глобальные переменные» и «Глобальные константы» на панели дизайнера открывают слайдер. Поля:
  «Название», «Тип», «Множественность», «Значение», «Видимость», «Описание».
- **Тип, множественность и видимость после сохранения не меняются** — ошибку исправляют новой записью.
- Глобальные переменные появились в bizproc 21.500.0; глобалы доступны и в роботах CRM.
- Процесс меняет только **глобальные переменные**: действиями «Изменение глобальных переменных»
  ([урок 23418](https://dev.1c-bitrix.ru/learning/course/?COURSE_ID=57&LESSON_ID=23418)) и «Выполнить
  математические операции» (результат пишется в глобальную переменную, урок 23564). В «PHP коде» —
  `GlobalVar::getById()` / `GlobalVar::upsert()`, значение в ключе `Default`
  ([урок 3806](https://dev.1c-bitrix.ru/learning/course/?COURSE_ID=57&LESSON_ID=3806)).
- В «Условии» и «Цикле» глобальные значения доступны только в условии «Смешанное».

## Почему это важно при внедрении

Глобалы — штатная замена [[antipattern-bizproc-hardcoded-portal-ids|зашитым в шаблон ID портала]]
(вывод команды). Шаблон, ссылающийся на глобальную константу, должен переноситься между порталами:
достаточно один раз задать значение на новом портале, а не править десятки шагов. **Не проверено:**
совпадёт ли ID глобала на другом портале без пересоздания через `upsert($id, …)` — книга сама берёт
глобал по ID; проверить перенос вживую.

## Подводные камни

- **`upsert()` принимает описание целиком.** Чтобы поменять одно поле, надо прочитать, изменить и
  сохранить — иначе затрёте остальные:

  ```php
  $prop = GlobalVar::getById($id);
  if ($prop === null) { throw new \Exception('Глобал не найден'); }
  $prop['Default'] = 'новое значение';
  GlobalVar::upsert($id, $prop);
  ```

- **Глобальную константу процесс не меняет, а человек и код — могут.** Курс называет глобальные
  константы неизменяемыми — в смысле «из процесса»: действия для них нет. Значение правят в слайдере
  или через API `GlobalConst::upsert()` (книга). **Константы шаблона** задаются в параметрах шаблона и
  во время выполнения доступны только на чтение (`getConstant()` в [[entity-cbp-activity|CBPActivity]]).
  Одинаковое слово «константа» означает две разные вещи.

> **Уточнено 2026-09-22.** Раньше здесь было «глобальные константы можно менять» без оговорки. Курс
> (уроки 23718, 26972) называет их неизменяемыми; противоречия нет — речь о процессе, а не об
> администраторе и API.
- **ID выглядит как `Variable1684762282405`** — имя вида «класс + отметка времени». Не
  конструируйте его вручную и не зашивайте в код: получайте через `getAll()` по имени (практика
  команды).
