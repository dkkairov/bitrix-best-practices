## TL;DR
Курс даёт смысл каждого поля заданий и конструкций. Главное для генерации и ревью: у четырёх заданий
общий срок в секундах, минутах, часах или днях; по его истечении утверждение автоматически отклоняется,
ознакомление и запрос информации завершаются сами. Результаты действий доступны в «Вставке значения →
Дополнительные результаты» сразу после добавления действия. «Условие» выполняет первую истинную ветку
слева, «и» сильнее «или», ветку «иначе» делают условием «Истина». «Параллельное ожидание действия» без
ветки-паузы зависает.

## Ключевые тезисы
- **Общее для действий (12321).** Одинаковым действиям давать разные заголовки: результаты в
  «Вставке значения» сгруппированы по заголовку. «[Ид]» — латиница, цифры и `_`; якорь `#<Ид>` в адресе
  дизайнера ведёт к действию. Выключенное действие (с bizproc 23.300.0) не выполняется, вложенные в
  выключенный блок — тоже.
- **«Запустить бизнес-процесс» (7721).** Поля «ID документа», «Шаблон», «Ожидать завершения
  бизнес-процесса», «Параметры бизнес-процесса». Результат — ID запущенного процесса. Автор нового
  процесса — автор исходного. Шаблон должен быть того же типа документа. ID документа CRM собирают с
  префиксом типа (`DEAL_…`); для смарт-процесса и счёта — через поле «Привязка к элементу CRM».
- **Результаты-ошибки (3785, 3777).** «Текст ошибки изменения» и «Текст ошибки создания» (с 23.200.0)
  пусты при успехе. Ловят смешанным условием «заполнено» и уведомляют ответственного.
- **Общие поля заданий.** Название и описание, текст статуса, поле пояснения (показ, обязательность,
  подпись), срок, «Ограничить доступ» (текст задания видит только исполнитель, в ленту не попадает),
  «Тип делегирования»: «Только подчиненным», «Всем сотрудникам», «Никому» — при первых двух в задании
  есть кнопка «Делегировать»; администратор делегирует и при запрете.
- **Срок.** Секунды, минуты, часы или дни; пусто или 0 — без срока, процесс ждёт исполнителя. Меньше
  «Минимального времени ожидания для действий» из настроек модуля задать нельзя — форма предупреждает.
- **По истечении срока:** утверждение — документ автоматически отвергнут, «Автоматическое отклонение»
  = 1; ознакомление и запрос информации — задание завершается автоматически, «Автоматическое …» = 1.
- **Утверждение (3771).** «Все сотрудники», «Любой сотрудник», «Голосование сотрудников»; для
  голосования — процент («Более скольки процентов…») и «Ожидать, чтобы проголосовали все…». 16
  результатов: ID, пояснения, счётчики и проценты голосов, последний голосовавший и его пояснение,
  утвердившие и отклонившие (списком и текстом), автоматическое отклонение.
- **Запросы информации (3782, 7839).** Задание видят все из «Заполняют сотрудники», выполняет первый
  приступивший. Поля запроса становятся переменными шаблона. У запроса с отклонением — «Текст кнопки
  отклонения», «Сохранять значения в случае отказа» (с bizproc 20.200.0), четыре варианта
  обязательности пояснения (с 21.400.0).
- **Условие (3789).** Ветки проверяются слева направо, выполняется первая истинная; если ни одна не
  подошла, конструкция пропускается. Виды: «Смешанное», «PHP код» (задаёт только администратор),
  «Значение переменной», «Поле документа», «Истина». «И» сильнее «или»; проверку «не равно» для
  нескольких значений строят только через «и» — с «или» она всегда истинна. «Содержится в» и
  «Содержит» чувствительны к регистру; «Между» — с 23.400.0.
- **Цикл (3792).** Повторяется, пока условие истинно; начатая итерация доходит до конца. В облаке не
  больше 1000 итераций, в коробке — настройка модуля (с 25.100.0).
- **Параллельное выполнение (3791).** Ветки слева направо; ожидание в одной не держит другие; дальше
  процесс идёт, когда завершены все.
- **Параллельное ожидание действия (3790).** Процесс уходит в ветку, чьё первое действие завершилось
  раньше, остальные отбрасываются. Ветка с «Паузой в выполнении» обязательна — иначе возможное
  бесконечное ожидание.
- **Итератор (10481).** Перебирает множественное значение, результаты «Ключ» (с нуля) и «Значение»
  (`Key`, `Value`).

## Открытые вопросы
- «Команда» и «Установить статус» — для каких типов процессов, кроме процессов со статусами.
- «Было изменено» — по курсу только для списков и ленты; как на текущих версиях в CRM.
