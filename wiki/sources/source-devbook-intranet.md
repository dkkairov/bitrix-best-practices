## TL;DR
Оргструктура и отсутствия построены на инфоблоках: подразделения — разделы, отсутствия — элементы.
Читать их удобнее через `CIntranetUtils` и D7-классы интранета, писать — средствами инфоблока, ID
инфоблоков брать из опций со значением по умолчанию `'-1'`. Темы оформления — пользовательская
настройка цвета и фона поверх шаблона `bitrix24`, а не инструмент кастомизации интерфейса.

## Ключевые тезисы
- Подразделение — раздел служебного инфоблока «Оргструктура»; руководитель — поле `UF_HEAD`; корень
  один на портал. От структуры зависят права на отделы и видимость отчётов подчинённых.
- ID инфоблоков — опции `intranet` / `iblock_structure` и `iblock_absence` (общие и для сайта).
  **Значение по умолчанию при чтении — `'-1'`, а не `0`:** ноль `getList` инфоблока отбрасывает, и
  при сбое настроек выборка осталась бы без фильтра.
- `CIntranetUtils::GetStructure()` отдаёт всё дерево (`TREE`, `DATA`), все ID — строки;
  `GetIBlockSectionChildren()` делает запросы в цикле, включает исходные ID, ключам не доверять;
  сотрудников — через `\Bitrix\Intranet\Util::getDepartmentEmployees()` (прокси в `CIntranetUtils`
  не рекомендован).
- Отсутствие — элемент инфоблока «График отсутствий» (`USER`, `ABSENCE_TYPE`, `NAME`,
  `ACTIVE_FROM`/`ACTIVE_TO`); вторая часть отсутствий — в «Календаре»; свои типы добавлять не
  рекомендуется. `UserAbsence::getIblockId()` — общий ID, может вернуть `0`. У типа отсутствия
  `ACTIVE` означает «это отпуск».
- `GetAbsenceData($params, $mode)` — режим по умолчанию `BX_INTRANET_ABSENCE_ALL` (календарь +
  график), `…_HR` — только график.
- CRUD-событий у отсутствий нет (события инфоблоков), но есть `OnStartAbsence`/`OnEndAbsence`.
- Тема: только цвет текста, фон и подложка; не больше 40 пользовательских тем; групповая тема
  меняется без проверки прав; управлять составом тем штатно нельзя.

**Возможное устаревание (§6).** Книга описывает оргструктуру на инфоблоке, а в REST уже есть методы
`humanresources.node.*` для отделов и команд (сверено через MCP 2026-09-21). Прежде чем писать в
инфоблок оргструктуры на свежей коробке, проверить, какая модель у вашей версии — пометка в
[[concept-org-structure]].

## Противоречия внутри книги
- Инфоблок оргструктуры назван единым на портал, но ID предлагается читать и для сайта.
- Ключ дерева в тексте — `THREE`, в примере — `TREE` (верен `TREE`).
- Пример обработчика `OnStartAbsence` подписан на модуль `'crm'`.
- Базовые группы тем: `default`/`light`/`black` в одном месте, `dark`/`light` — в другом; про
  `$entityId` таблица параметров и пример использования расходятся.
